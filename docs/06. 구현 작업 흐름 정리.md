# 구현 작업 흐름 정리

작성일: 2026-05-23

이 문서는 `docs/05. 통신 API 설계.xlsx`와 `docs/03. ERD.drawio`를 참고하여 이번 피드에서 진행한 컨트롤러 및 서비스 구현 흐름을 순서대로 정리한 것이다.

## 1. API 설계 문서 확인

먼저 `docs/05. 통신 API 설계.xlsx`의 RESTful API 시트에서 필요한 API 항목을 추출했다.

확인한 주요 항목은 다음과 같다.

- 저장된 영상 목록(세그먼트 단위 조회)
- 저장된 영상 목록(타임라인 단위 조회)
- 영상 범위 재생
- 구간 다운로드
- 특정 세그먼트 조회
- 개별 세그먼트 재생
- 개별 세그먼트 다운로드
- 썸네일
- 이벤트 리스트 조회
- 이벤트 디테일 조회
- 이벤트 실시간 구독
- 로그인, 로그아웃, 회원가입, 토큰 갱신, 내 정보 조회/수정/탈퇴

엑셀 파일은 `openpyxl`이 없는 환경이었기 때문에 `.xlsx` 내부 XML을 Python 표준 라이브러리(`zipfile`, `xml.etree.ElementTree`)로 직접 읽어 필요한 행을 추출했다.

## 2. 기존 컨트롤러 구조 파악

`VmsDeviceController`를 기준 포맷으로 삼아 현재 프로젝트의 컨트롤러 작성 방식을 확인했다.

확인한 패턴은 다음과 같다.

- 각 handler 함수 안에서 `httpServer.addRoute(...)` 호출
- 요청 파라미터는 `req.getPathParam(...)`, `req.getQueryParam(...)` 사용
- JSON 응답은 `nlohmann::json`으로 구성
- 응답은 `Http::Response`에 status, header, body를 직접 설정하거나 `VmsApiResponse` 헬퍼 사용

이후 구현에서는 가능한 한 이 형식을 유지했다.

## 3. VmsPlaybackController 구현

대상 파일:

- `include/vms-api/VmsPlaybackController.h`
- `src/vms-api/VmsPlaybackController.cpp`

헤더에는 이미 필요한 함수 선언이 존재했으므로 `VmsPlaybackController.cpp`의 빈 handler를 채웠다.

구현한 라우트는 다음과 같다.

- `GET /devices/{deviceId}/playback/segments`
- `GET /devices/{deviceId}/playback/timeline`
- `GET /devices/{deviceId}/playback/stream`
- `GET /devices/{deviceId}/playback/download`
- `GET /playbacks/{segmentId}`
- `GET /playbacks/{segmentId}/stream`
- `GET /playbacks/{segmentId}/download`
- `GET /playbacks/{segmentId}/thumbnail`

처리 내용:

- 엑셀 문서의 예시 응답을 기준으로 샘플 JSON 응답 작성
- 영상 스트림, 다운로드, 썸네일 API는 실제 바이너리 파일 전송 대신 placeholder body 반환
- `Content-Length`는 placeholder body 길이와 문서상의 값이 다르면 클라이언트가 대기할 수 있어 수동 설정하지 않고 서버 직렬화가 자동 설정하도록 정리
- 문서에 있는 `hight` 오타와 일반적인 `height` 쿼리 파라미터를 둘 다 허용
- 라우트 등록은 컨트롤러 생성 시 활성화되도록 생성자에서 호출

검증:

- `g++ -std=c++17 -fsyntax-only`로 `VmsPlaybackController.cpp` 단독 문법 검사 통과

## 4. VmsEventController 구현

대상 파일:

- `include/vms-api/VmsEventController.h`
- `src/vms-api/VmsEventController.cpp`

`VmsEventController`는 파일과 함수 선언이 이미 존재했지만 handler 내부가 비어 있었다.

구현한 라우트는 다음과 같다.

- `GET /events`
- `GET /events/{eventId}`
- `GET /events/ws`

처리 내용:

- 이벤트 리스트 조회는 문서의 예시 이벤트 배열을 JSON으로 반환
- 이벤트 디테일 조회는 path parameter의 `eventId`를 반영하여 상세 JSON 반환
- 이벤트 실시간 구독은 `httpServer.addWebSocketRoute(...)` 사용
- WebSocket 연결 후 샘플 이벤트 JSON을 `sendText()`로 전송하고 정상 종료
- 인증 실패 시 401/403을 반환할 수 있도록 handshake handler 위치를 마련

검증:

- `g++ -std=c++17 -fsyntax-only`로 `VmsEventController.cpp` 단독 문법 검사 통과

## 7. VmsUserService 실제 로직 구현

대상 파일:

- `src/vms-api/VmsUserService.cpp`

레거시 `VmsClientUserService`의 흐름을 참고하여 현재 프로젝트 구조에 맞게 구현했다.

구현한 내용:

- `sha256_hex` 기반 비밀번호 해시 검증
- access token, refresh token 발급
- access token 만료 시간: 3600초
- refresh token 만료 시간: 604800초
- 프로세스 메모리 기반 token session map 관리
- 만료 token pruning
- logout 시 access/refresh token 제거
- refresh token 사용 시 기존 refresh token 폐기 후 새 access/refresh token 발급
- 회원가입 시 사용자 생성 후 승인 대기 레코드 생성
- 로그인 시 승인 상태 확인
- 내 정보 조회 시 역할 목록 조회
- 내 정보 수정 시 현재 비밀번호 확인 후 이름/비밀번호 수정
- 회원 탈퇴 시 현재 비밀번호 확인 후 `is_active = false` 처리 및 세션 제거

로그인 상태별 처리:

- 아이디/비밀번호 불일치: `InvalidCredentials`
- 승인 대기: `PendingApproval`
- 승인 거부: `Rejected`
- 비활성 사용자: `Inactive`
- 정상 로그인: access/refresh token 발급

## 8. VmsUserController 구현

대상 파일:

- `src/vms-api/VmsUserController.cpp`

문서의 `/users/...` 경로에 맞게 기존 `/user/...` 라우트를 교체했다.

구현한 라우트:

- `POST /users/login`
- `POST /users/logout`
- `POST /users/signup`
- `POST /users/token/refresh`
- `GET /users/me`
- `PATCH /users/me`

구현한 공통 처리:

- JSON body parse 및 object 검증
- 필수 필드 타입 검증
- `Authorization: Bearer <token>` 추출
- access token 검증 후 `/users/me` 계열 API 처리

주요 에러 응답:

- `INVALID_ARGUMENT`

- `AUTH_ACCOUNT_PENDING_APPROVAL`
- `AUTH_ACCOUNT_REJECTED`
- `AUTH_ACCOUNT_INACTIVE`
- `AUTH_INVALID_TOKEN`
- `AUTH_INVALID_REFRESH_TOKEN`
- `AUTH_LOGINID_ALREADY_EXISTS`
- `AUTH_INVALID_PASSWORD`

## 10. main.cpp 런타임 연결

대상 파일:

- `src/main.cpp`

사용자 API가 실제 서버에서 동작하려면 DB 설정과 컨트롤러 생성이 필요했다. 기존 `main.cpp`는 서버만 생성하고 controller/service를 생성하지 않았으므로 최소 연결을 추가했다.

추가한 내용:

- `AppDb::configure(config.dbConninfo, config.dbMapperPath)` 호출
- `VmsUserService userService` 생성
- `VmsUserController userController(server, userService)` 생성
- `server.start()` 실패 시 `return 1`
- 서버 프로세스가 바로 종료되지 않도록 유지 loop 추가
