# Media Server 개발 작업 목록

이 문서는 VMS 서버의 media-server 기능을 구현하기 위한 작업 목록을 정리한다. 목표는 실시간 다중 스트리밍과 저장 영상 기반 플레이백을 모두 지원하는 것이다.

## 현재 진행 상황

> 진행 상태 표기: `[x]` 완료, `[~]` 부분 구현 또는 runtime 검증 필요, `[ ]` 미구현

현재 `lib/app-media-server`는 첫 live ingest PoC에서 **H.264 RTSP 다중 수신 + MP4 segment 녹화 PoC**로 확장 중이다.
기존 `MediaLiveStreamService`는 제거되고, 카메라별 worker와 pipeline을 관리하는 구조로 교체되었다.

완료된 것:

- `lib/app-media-server` 독립 모듈 생성
- 루트 CMake에 `app-media-server` 연결
- GStreamer 기반 media backend 선택
- `CameraManager`에서 카메라 등록/제거 및 전체 worker 시작/정지
- 카메라별 `CameraWorker` thread와 독립 `CameraPipeline` 구성
- H.264 RTSP/RTP depay/parse pipeline 구성
- `tee`를 이용해 녹화 branch와 decoded frame `appsink` branch 분리
- `splitmuxsink` 기반 MP4 segment 생성 및 segment 길이 설정
- segment 시작/종료/interrupted 상태를 메모리에 기록
- cameraId와 시간 범위가 겹치는 segment 조회
- GStreamer `ERROR`/`EOS` 감지 후 3초 간격 자동 재연결
- 종료 시 EOS를 보내 마지막 segment finalize 시도
- `src/media/MediaService`를 통해 ONVIF provisioning 결과를 `CameraConfig`로 변환
- ONVIF `GetStreamUri` 결과 RTSP URL을 `CameraManager::add_camera()`에 연결
- `application.yml`의 `app.media.recording.rootDir`, `splitSeconds`로 녹화 경로와 segment 길이 설정
- `CameraManager`가 runtime에서 시작되고, 이후 등록되는 ONVIF 카메라는 즉시 worker 시작
- CPack 패키지에 media pipeline에 필요한 GStreamer plugin과 `gst-plugin-scanner` 포함
- 새 `CameraManager` 기반 구현을 포함한 전체 빌드 및 TGZ 패키징 통과
- `RtspRelayServer`를 application lifecycle에 연결하고 ONVIF profile별 RTSP relay mount 동적 등록
- relay mount를 `<device-name-slug>__ch<channel_id>__<profile-token>`으로 생성
- `channels.service_rtsp_url`에는 VMS relay URL, `profiles.cctv_rtsp_url`에는 ONVIF 원본 URL 저장

현재 구현 중이거나 검증이 필요한 것:

- 실제 카메라 RTSP URL을 사용한 end-to-end runtime 테스트
- 패키지 배포본에서 bundled GStreamer plugin만으로 element 생성이 정상 동작하는지 검증
- segment 시각은 media timestamp가 아니라 callback 시점의 system clock 사용
- segment metadata는 process-local memory에만 존재하며 재시작 시 소실
- 녹화 pipeline의 `appsink` branch와 RTSP relay는 아직 packet/pipeline을 공유하지 않으며, relay가 별도 upstream 연결을 사용함
- ONVIF profile별 stream을 모두 등록하므로, 장비에 profile이 많을 때 녹화 대상 선택 정책 필요
- 현재 영상 codec은 H.264만 지원

현재 pipeline:

```text
rtspsrc
  -> rtph264depay
  -> h264parse
  -> tee
      -> queue -> splitmuxsink -> MP4 segment files
      -> queue -> avdec_h264 -> videoconvert -> videoscale
               -> RGB 640x360 -> appsink
```

아직 하지 않은 것:

- RTSP 인증 옵션 모델
- TCP/UDP transport 선택 옵션과 timeout 설정
- 지수 backoff 및 최대 재시도 정책
- H.265/audio 녹화
- 녹화 ingest와 upstream 연결을 공유하는 live relay 최적화
- playback/seek/download
- 영속 segment metadata/DB 연결
- HTTP API 연결
- ONVIF profile/stream 녹화 대상 선택 정책
- retention 및 저장 용량 관리

## 목표 기능

media-server가 담당할 큰 기능은 다음과 같다.

- 실시간 다중 스트리밍
- RTP/RTSP 기반 live stream 수신 및 중계
- 저장 영상 segment 관리
- timeline 기반 저장 영상 조회
- 저장 영상 범위 재생
- 재생 중 seek 지원
- 구간 다운로드
- 특정 segment 조회
- 개별 segment 재생
- 개별 segment 다운로드

## 전체 구성 방향

예상 구성은 다음과 같다.

```text
ONVIF Discovery / Media
  -> RTSP URL 확보
  -> Stream Ingest
  -> RTP/RTSP Session
  -> Recorder
  -> Segment Store
  -> Playback Service
  -> API / Player
```

역할을 나누면 다음과 같다.

- `Media Source Registry`: ONVIF로 얻은 profile/RTSP URL을 stream source로 등록한다.
- `Stream Ingest`: 카메라 RTSP/RTP stream을 수신한다.
- `Session Manager`: 카메라별 live stream 연결 상태와 재연결을 관리한다.
- `Live Session Manager`: 클라이언트별 live view session을 생성하고 stream에 attach/detach한다.
- `Relay Service`: 하나의 upstream ingest를 여러 클라이언트에게 전달한다.
- `Recorder`: live stream을 저장 가능한 segment로 쪼갠다.
- `Segment Store`: segment 파일과 metadata를 관리한다.
- `Timeline Index`: 시간 범위 기반 조회를 위한 index를 유지한다.
- `Playback Service`: 저장 영상을 시간 범위 또는 segment 단위로 재생한다.
- `Download Service`: 저장 영상 구간 또는 segment를 다운로드 파일로 만든다.
- `Media API`: live/playback/download를 외부 API로 노출한다.

## ONVIF와 Live Stream 연결 설계

`mediaXAddr`는 media-server에 바로 넣어 재생하는 값이 아니다. `mediaXAddr`는 ONVIF Media Service endpoint이며, 이 endpoint로 `GetProfiles`, `GetStreamUri`를 호출해서 최종 RTSP URL을 얻어야 한다.

```text
Discovery
  -> Device.GetCapabilities
  -> mediaXAddr 확보
  -> Media.GetProfiles
  -> Media.GetStreamUri(profileToken)
  -> rtspUrl 확보
  -> Media Source Registry에 등록
  -> CameraConfig 구성 후 CameraManager.add_camera()
  -> CameraManager가 실행 중이면 해당 CameraWorker 즉시 시작
```

카메라 원본 RTSP 연결과 클라이언트 연결은 분리한다.

```text
Camera RTSP upstream connection: 1개
Client live viewer sessions: N개
```

같은 카메라/profile을 여러 클라이언트가 요청하면 media-server는 카메라에 RTSP 연결을 여러 개 만들지 않고, 기존 ingest session에 viewer session을 attach한다.

현재 구현된 연결:

```text
OnvifDeviceProvisioningService::provisioningLoop()
  -> ProvisioningResult 생성
  -> MediaService::addCamera(results)
  -> OnvifProvisioningRepository::upsert(results)
  -> profile.streamUri.uri 확인
  -> camera_id = <endpointReference/deviceUrl>__<profileToken>
  -> record_pattern = <app.media.recording.rootDir>/<camera_id>/%05d.mp4
  -> CameraManager::add_camera(config)
```

현재 설정:

```yaml
app:
  media:
    recording:
      rootDir: "recordings/onvif"
      splitSeconds: 5
```

예상 source 모델:

```cpp
struct MediaStreamSource {
    std::string streamId;
    std::string cameraId;
    std::string profileToken;
    std::string rtspUrl;
    bool recordingEnabled = false;
    bool alwaysOn = false;
};
```

예상 viewer session 모델:

```cpp
struct MediaLiveViewerSession {
    std::string sessionId;
    std::string streamId;
    std::string userId;
    std::chrono::system_clock::time_point createdAt;
    std::chrono::system_clock::time_point lastAccessedAt;
};
```

클라이언트 live 요청 흐름:

```text
POST /api/media/live-sessions
  -> cameraId/profileToken 확인
  -> MediaStreamSource 조회
  -> ingest session이 없으면 startStream(rtspUrl)
  -> ingest session이 있으면 재사용
  -> viewer session 생성
  -> playUrl 반환
```

응답 예시:

```json
{
  "sessionId": "live-abc",
  "streamId": "camera-1-main",
  "playUrl": "/api/media/live-sessions/live-abc/stream",
  "transport": "hls"
}
```

운영 정책은 두 가지를 함께 지원한다.

- `alwaysOn`: 녹화 대상 stream처럼 항상 ingest를 유지한다.
- `lazyStart`: 클라이언트가 요청할 때 ingest를 시작하고, viewer가 없으면 idle timeout 후 중지한다.

권장 정책:

```text
recordingEnabled == true
  -> always-on ingest

live view only
  -> lazy start
  -> viewerCount == 0 && idleTimeout expired
  -> ingest stop
```

## 19. Packaging / 배포

media-server는 GStreamer plugin이 시스템에 설치되어 있지 않으면 element 생성 단계에서 실패한다. 배포 패키지는 현재 pipeline에 필요한 최소 plugin과 plugin scanner를 함께 포함한다.

포함 대상:

```text
libgstrtsp.so              # rtspsrc
libgstrtp.so               # rtph264depay
libgstrtpmanager.so        # rtpbin (RTSP RTP/RTCP session)
libgstudp.so               # udpsrc/udpsink (RTSP over UDP)
libgsttcp.so               # TCP network elements
libgstvideoparsersbad.so   # h264parse
libgstmultifile.so         # splitmuxsink
libgstlibav.so             # avdec_h264
libgstvideoconvertscale.so # videoconvert, videoscale
libgstcoreelements.so      # queue, tee, capsfilter
libgstapp.so               # appsink
libgstisomp4.so            # mp4mux
libexec/gstreamer-1.0/gst-plugin-scanner
```

RTSP relay 런타임 library도 패키지 `lib`에 명시적으로 포함한다.

```text
libgstrtspserver-1.0.so.0  # GstRTSPServer
libgstrtsp-1.0.so.0        # RTSP core, transitive dependency
```

runtime에서는 패키지 내부 plugin을 우선 사용하도록 `main.cpp`에서 다음 환경변수를 설정한다.

```text
GST_PLUGIN_PATH=<install-root>/lib/gstreamer-1.0
GST_PLUGIN_SCANNER=<install-root>/libexec/gstreamer-1.0/gst-plugin-scanner
```

작업 목록:

- [x] CPack에 필수 GStreamer plugin 설치 규칙 추가
- [x] CPack에 `gst-plugin-scanner` 포함
- [x] CPack에 `libgstrtspserver-1.0.so.0`, `libgstrtsp-1.0.so.0` 명시 포함
- [x] `/../lib`를 전이 dependency에도 적용하도록 실행 파일에 DT_RPATH 설정
- [x] plugin 의존 shared library를 `file(GET_RUNTIME_DEPENDENCIES)`로 패키지에 포함
